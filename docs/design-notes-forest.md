# Forest 阅读记录与时光花园的设计取舍

记录日期：2026-10-25。本文是项目设计笔记；“建议”均未作为功能实现。

## 阅读范围

已阅读用户保存的《[产品分析：Forest 专注森林](https://www.woshipm.com/evaluating/1053804.html)》正文，作者 lrccy，发表于 2018-06-11，体验版本为 4.1.2、iOS 11.1.2。另查看其“我的森林”配图：同一页面把森林、每日柱形图、总时长和日期放在一起。原网页、配图及个人文件不随本插件分发。

文章提供的设计线索是：入口简短、时间转化为植物、回顾时兼有画面与数字、逐步获得新内容。文中人口属性和市场表现的解释属于作者当时的分析，不足以证明性别、地域或年龄与自制力的因果关系，也不能直接当作本插件用户画像。旧价格、排名及付费方案不用于本项目判断。

[Forest 官方首页](https://www.forestapp.cc/)目前仍以计时、生长和完成后的森林作为核心表达；这次对照以用户保存的旧文章为主，不声称完整评测了最新版 Forest。

## 我们自己的产品基础

时光花园已经有八种植物、分类/程序/网站规则、可跨天的累计生长、可选中断扣减、周相册和单花详情。0.10.0 将周选择改成从早到晚的纵向时间线，选中周的缩略图紧接日期，四角远景增加层次。它们解决的是浏览与氛围，不代替时间回顾。

目前核心记录的边界很明确：

- 同时只养一盆，只认可运行中实际观察到的匹配前台时间；离开电脑、重启、休眠间隔不补算。
- 成熟花保存 id、名称、品种、种下/开花时间、目标时长及完成进度，不保存当时规则或逐日累计流水。
- Hindsight 分类是匹配依据，不能推断“这个人真正专注、学习或有成效”。
- 七项 API 权限不包括任意文件读写、程序启动、应用拦截或桌面悬浮能力。插件页面与后台通过 SQLite 协作，不能依赖页面变量跨运行环境共享。

因此，最适合的方向是：**把已经选择的电脑活动变成可回顾的花园，同时减少每次重新设置的操作。**

## 建议顺序

| 优先级 | 建议 | 在我们这里怎么做 | 需要先解决什么 |
|---|---|---|---|
| 1 | 周回顾 | 日期旁显示本周开花数、品种数及已完成花朵的目标分钟合计；与时间线共用同一周选择。未开花的当前盆栽另列，不混进已完成总数 | 标为“完成目标时长”，不能叫“本周实际专注时长”：一朵跨周生长的花会全部归到开花周，惩罚前累计时间也无法从成熟记录复原 |
| 1 | 保存种植方案 | 保存“阅读 30 分钟”“编程 60 分钟”等名称、规则、时长与惩罚设置；开花后可沿用上次方案，仍由用户确认播种 | 用分类 ID 匹配，缺失分类先说明；方案预览要明确本次是否启用惩罚，避免悄悄沿用严格设置 |
| 2 | 真正的每日生长图 | 增加周一至周日七根小柱，查看自己哪天养了多久。后台将有效累计按本地日期记账；扣减单列，显示累计/扣减/净进度 | 需要新增每日汇总持久化，并与原有 SQLite/CAS 更新原子提交。跨午夜、夏令时、重试、配额和中断都要验证；旧数据标“无逐日记录”，不补造历史 |
| 2 | 轻量收藏里程碑 | 如首次开花、收集不同品种、累计完成若干盆，奖励边角装饰或可选主题；展示已达成与下一步 | 指标只来自现有记录。若依赖可删除收藏，就明确是“当前收藏进度”；若要永久成就，需另存达成事实，避免删花后被撤回 |
| 2 | 给花留下任务记忆 | 种下时可写一句“读完某章”“写完测试”，详情侧栏展示；可选单独标签，先不做复杂任务系统 | 新增自愿填写的短备注和上下文快照，旧花保持空白。规则只表示允许活动，不能把一条花的时长拆分给多个分类，也不能为旧花猜分类 |
| 3 | 可选的花园主题 | 春日、雨后、黄昏只改变背景和装饰；保留同一投影、花位及低频动效。由用户选择，不根据真实时间强制改变 | 缩略图维持可辨识；主题不能靠更多高频动画堆效果，也不能让装饰挡花或压低小窗口可读性 |
| 3 | 本地分享卡 | 将用户选定一周的花园和概况画成一张图，可预览并选择是否包含备注 | 先验证宿主沙箱允许的导出/下载方式。不能预先承诺任意写盘或自动上传，也不把个人活动明细默认放进图片 |

前两项投入相对小，能让“种完以后回来看看”和“下一次开始”连接起来。真正的每日图有价值，但属于数据功能，应另作一轮实现与验证，不借本次界面调整顺带改动生长算法。

## 现在不照搬的部分

- **强制离开即死亡、默认枯花、连续签到清零**：桌面工作经常需要切换文档、浏览器、通讯工具。继续默认暂停不惩罚，让严格模式保持自愿；也不以外观变化偷偷引入惩罚。
- **直接复制金币商店与稀有度经济**：目前植物只有八种，先让基础收藏与装饰里程碑有意义，不增加刷时长、买解锁或重复确认的负担。
- **好友竞争、多人连坐**：需要账户、服务端、同步、身份和隐私设计；不是现有离线插件的小改动。
- **真实植树与公益兑换**：需要实际合作与资金履约，不能把虚拟装饰描述为现实公益结果。
- **3D 旋转或自由摆放作为下一步**：目前等距素材是二维绘画，旋转会露出透视问题。先做好对齐、选中、回顾和轻量主题，再考虑可持久化的位置编辑。

## 实现与建议的界线

0.10.0 只实现时间线和四角美化，维持原有生长、存储和权限。表中的方案、统计、成就、任务备注、主题选择与分享均为后续建议。所有验证使用隔离演示数据，未读取个人 Hindsight 数据库。
