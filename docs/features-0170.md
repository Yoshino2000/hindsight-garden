# 0.17.0：轻风与更稳妥的刷新

基础功能已经可用，仍在开发迭代，未经严格全面测试，可能存在问题和风险。[安装说明](usage.zh-CN.md) · [English guide](usage.en.md) · [完整审查](audit-0170.md) · [最终验证](verification.md)

## 花朵一起迎风

八种花和隐藏配色共用一阵轻风，四个主题都适用。最终幅度约 1.2–2 度，一阵持续 4.5 秒，随后静歇 3–10 秒。贴地小椭圆影以相同节奏缓动，采用低精度变换；不逐帧计算真实光照，也不增加植物贴图。

![0.17.0 花园轻风与贴地阴影](screenshots/breeze.jpg)

同一时刻最多一个共享定时器；没有每株花各自的计时器。相册缩略图静止。切换花园会结束当前阵风并重新等待；关闭动效、隐藏页面、离开花园、进入紧凑模式或系统要求减少动态时停止。环境动效的开关不改变植物生长规则。

## 修正计时与旧后台干扰

- 慢写入时，活动切换按 Worker 收到事件的时刻结算，避免把排队等待误算成原程序的使用时间。
- 墙钟倒退后，旧排队事件不会重新激活生长。
- 被替换的旧 Worker，其迟到错误和恢复尝试不能清除新 Worker 的活动或抢回所有权；首次启动已写入但回执丢失的情况也覆盖在内。
- 热状态和归档版本到达安全整数上限时，拒绝继续增加，保留最后可读数据。
- 旧归档额外元数据嵌套很深时，使用迭代复制和冻结，避免读取栈溢出。超过 SQLite JSON 编辑深度的旧记录可以查看、手动移除；改名或备注会明确拒绝并原样保留，不承诺无限深编辑。

以上均有受控复现与回归测试，触发方式、代码和测试名称见[审查报告](audit-0170.md)。这些结果不等于所有真实宿主、磁盘和睡眠场景均已验证。

## 大收藏少做重复工作

未变化的收藏使用同一份只读冻结快照，花园视图直接复用。花圃只比较可见 25 株的展示字段，相册只比较至多 300 株的图像字段；改备注时保留花圃节点并更新详情。未变化的统计不重新建 DOM。页面不可见时停止界面轮询，恢复可见时请求刷新；后台仍按 Hindsight 的活动事件生长。

首次载入、收藏变化，以及首次切换页或周仍需要处理归档；收藏较大时仍可能等待。[审查报告](audit-0170.md)分别列出 Node/V8 与内存 SQLite 基准，未将它们换算为整体 CPU 百分比，也未据此声称原生宿主或 GPU 性能。

日期直达支持 1970–9999 年，早于范围会明确报错；UTC+13 的最早一天也能正确找到 1969 年 12 月 29 日开始的周。空分类名的内置占位语随中英日界面翻译，用户自己填写的分类名保持原样。

## 数据与验证边界

沿用 schema 2、成就 revision 4、七项权限和 64 MB。植物 PNG、图标、几何落点、八种隐藏配色规则、52 级／26 张成就卡均保持不变，不重抽隐藏结果或重写既有成就日期。

升级前保留一致备份；不要混跑新旧版本或直接降级。最终测试数量和本轮浏览器检查以[验证记录](verification.md)为准。没有读写个人 Hindsight 数据库，没有安装最终原生 ZIP；操作系统通知、真实 SVG GPU 开销与长期性能尚未验证。轻风截图为本版示例，其余首页截图保留 0.16.0 及更早的演示，部分为中文。
